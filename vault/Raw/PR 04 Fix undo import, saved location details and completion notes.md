# PR #4: Fix undo import, saved location details and completion notes

https://github.com/RigoM7/Rigo-App/pull/4 · state: closed · merged: 2026-10-05T15:28:03Z

## Summary
Group 1 bug fixes from the 370 Enviro test run.

**1. Undo import was always disabled**
- **Cause:** the screen and the server compared the list with a *text* snapshot taken at import time. Supabase stores the workspace as `jsonb`, which reorders object keys on save, so after the first save the text never matched.
- In the live workspace, the Clients, Equipment, Service locations, Team and Vehicles imports were identical by value but failed the text comparison.
- **Fix:** compare by value, in one shared rule (`rigoUndoBlocker`) used by both the server and Import history. Existing snapshots keep working with no data rewrite.
- A disabled button now explains why (also shown as a tooltip): a newer import into the same list, records changed since the import, imported records linked to jobs or other records, or already undone.

**2. "Use saved location details" filled nothing in**
- **Cause:** it read `address`/`type`/`lat`/`lng` fields that no Service locations list had. Fields added in the list builder get random IDs, so they could never match. Choosing a location also blanked an address the user had typed.
- **Fix:** Service locations get default fields: street address, city, state, postal code, location type, latitude, longitude, linked client, site contact name/phone and access notes.
  - Existing workspaces receive them once through a versioned upgrade in the normalizer.
  - A user field with the same name (e.g. "Address") is reused, not duplicated.
- Fields are looked up by ID, then by name. Typed values are never overwritten with blanks.
- If a location has no details saved, an inline message says so.
- New jobs also take address, type and coordinates from the chosen location on the server.

**3. Completion notes were pre-filled with the dispatcher's notes**
- **Cause:** completion reused the job's `notes` field. Opening a job copied the team notes into the completion box, and completing saved the box back over them, keeping the team notes when the box was empty.
- **Fix:** completion text is stored in `completionNotes`. The box starts empty, and team notes appear read-only above it. The server never changes `notes` on completion.
- Jobs completed before this change are not rewritten. Their text is shown as "Notes recorded at completion".

**Server:** workspaces are normalized when read, so older workspaces show the new defaults without needing a save first. If normalizing ever fails, the read falls back to the stored data rather than blocking access. There are no SQL schema changes: list fields live inside the workspace JSON, and RLS and server-side access checks are unchanged.
