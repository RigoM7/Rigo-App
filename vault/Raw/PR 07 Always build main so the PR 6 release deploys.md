## Summary
The squash merge of #6 kept the work-in-progress `[checkpoint]` lines in its message body, so Vercel's ignore step skipped the production build. A redeploy was skipped as well. As a result, production still runs the code from before #6. The database already has all of #6's additive changes, which the old code ignores.

This PR changes the skip rule in `vercel.json` so that:
- `main` always builds;
- on other branches, only a commit whose first line contains `[checkpoint]` is skipped;
- commits that touch only `.claude/` or `CLAUDE.md` are still skipped, as before.

`CLAUDE.md` is updated to match.

Merging this deploys #6 together with the fix, in one production build.
